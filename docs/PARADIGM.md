# 平衡岛范式（The balance_island Paradigm）

> `balance_island 平衡岛` 的设计宪法。本文件定义**它是什么、不是什么**，
> 以及可写进代码与契约的规则。所有实现与改动必须能对照本文件判定。
> 版本：v0.2.0（2026-11-14）

---

## 0. 一句话

**平衡岛是屏幕顶部的一枚注意力配重，不是一块状态舞台。**

它不替你完成任务，也不替系统展示状态；它只负责在「我需要知道」与
「我不想被打断」之间维持平衡：**该出现时出现，该退让时退让，该消失时消失。**

### 理论锚点：「平衡」不是隐喻

「平衡」有直接的学术出处，不是取一个好听的名字：

- Horvitz 等，***Balancing Awareness and Interruption: Investigation of Notification
  Deferral Policies***（Microsoft Research）——提出 **bounded deferral**：忙时延迟投递，
  在 `busy → available` 的状态转换点送出，若超过 `deferral bound` 则强制投递。
- Achloptas & Horvitz, *Principles of Bounded Deferral for Balancing Information
  Awareness with Interruption* —— 把它形式化为在「延迟界」与
  `expected cost of delayed attention` 之间求最优。
- Horvitz / Jacobs / Hovel, *Attention-Sensitive Alerting*（UAI'99）——
  「human attention is the most valuable and scarcest commodity」。
- 上位哲学：Mark Weiser & John Seely Brown 的 **Calm Technology**（1995，
  「simplify complexities, not introduce new ones」）与 MIT Media Lab 的
  **Ambient Displays / peripheral awareness**（ambientROOM, CHI'98）。
- 一瞥可读：Matthews 等 *Designing Glanceable Peripheral Displays*
  （UCB/EECS-2006-113, DIS'06）—— 同屏可扫元素约 ≤4 个工作记忆块，
  理解预算约 2 秒。

因此可把「平衡」写成**可断言的守恒条件**，而不是一句口号：

```
attention_cost   <= CAP_A   （注意力不被透支：显示量、动效、并发有硬上限）
information_loss <= CAP_I   （信息不丢失：L3 必须降级投递而非静默丢弃）
```

用户可以在边界内调偏好，但**不能关掉边界**——这同时划开了两条极端：
Rainmeter / Übersicht 式「无限自由、零节制」，与系统组件式「有节制、零调节」。
详细规则编号（R1–R119）与出处见 [调研对比结论](research/landscape.md)。

### 三个空白位

现有品类占住了「全给」（皮肤仪表）、「全藏」（菜单栏管理）、
「系统限定」（Live Activities / Widgets）、「随便改」（shell 注入）四个角，
中间三处仍是空的，平衡岛据此定位：

1. **有节制的可编程常驻态** —— 允许外部程序推送，但层级/并发/对比度/动效
   由系统常量锁死
2. **持续状态（无始无终）** —— Live Activities 只服务 ≤8h 的事件，
   Widgets 明确不支持连续实时更新；「持续存在的低幅度波动状态」无对应品类
3. **把「显示多少」本身当作被设计的量** —— 现有工具都把显示量当用户配置项，
   而非系统的核心不变量

## 1. 与灵动岛的三条分界

灵动岛（Apple Dynamic Island）解决的是「硬件挖孔如何变成有用的信息区」，
其设计重心是**展示、动效与系统级活动**；桌面没有挖孔，照搬只会得到一个
挡在标题栏上的悬浮面板。平衡岛从这里分开：

| 维度 | 灵动岛 / 同类桌面复刻 | 平衡岛 |
|---|---|---|
| 本体 | 系统状态的**舞台**，强调呈现 | 注意力的**配重**，强调克制 |
| 目标 | 让信息更醒目、动效更连贯 | 让信息**恰好够用**，且不打断当前任务 |
| 深度操作 | 在岛内完成（控制面板、多标签、小工具） | **回原应用**：岛内只保留最小必要控制 |
| 安静态 | 仍是胶囊，持续占据顶部 | 缩成一枚呼吸点，只回答「还在不在跑」 |
| 遮挡 | 常驻置顶，用户绕开它 | 可随时**让路**（穿透 + 降透明） |
| 数据来源 | 多为手动录入的待办 / 脚本注入 | **真实系统活动**为主，脚本注入为补充 |
| 视觉母题 | 玻璃、膨胀动效、整圈高光 | 顶部亮区 + 整圈淡描边，**不镀铬** |

### 三条公理

1. **岛不是操作台。** 单击是「披露」不是「进入应用」，点标题是「回原应用」不是
   「在岛里打开功能」。岛内只保留两类操作：切换焦点、对媒体的最小必要控制。
2. **存在感要可确认，但不能常驻占用。** 完全消失会让用户怀疑程序已退出；
   一直挂着胶囊则是噪音。安静态用一枚低透明度呼吸点解决这个矛盾。
3. **用户永远拥有让路权。** 任何情况下，用户都能用一个即时手势让岛不挡住
   背后的内容；岛不得依赖"关掉程序"来解除遮挡。

## 2. 核心概念：三条平衡轴

| 轴 | 两端 | 平衡机制 |
|---|---|---|
| **注意力** | 全知 vs 专注 | 信息按「是否现在需要处理」分级，默认只显示 1 条主信息；其余退为小圆 |
| **存在感** | 常显 vs 消失 | 三态：活跃（胶囊）/ 休眠（把手）/ 安静（呼吸点），按活动与交互自动迁移 |
| **控制权** | 系统推送 vs 用户决定 | 可 dismiss 单条、暂停 30 分钟、静默某类源、按 Ctrl 让路；配置本地且可迁移 |

### 信息分级（决定谁占主位）

| 级 | 含义 | 呈现 |
|---|---|---|
| L0 安静 | 无活动 | 呼吸点 |
| L1 环境 | 电量/音量/剪贴板等被动状态 | 短档胶囊，不主动展开 |
| L2 进行中 | 正在播放、正在跑的 Agent、下载、会议 | 胶囊主位 + 进度/状态 |
| L3 需处理 | 用户刚复制、通知到达、会话等待输入 | 短时提升到主位，随后自动回落 |

**回落是范式的关键**：任何 L3 都不永久占据主位，超时或被处理后必须退回，
否则岛会退化成通知栏。

## 3. 布局规则（对应代码常量）

| 规则 | 值 | 理由 |
|---|---|---|
| 安全区 | 工作区顶部内缩 ≥ 4px，锚点左/中/右三档 | 避让窗口标题栏；按工作区而非屏幕物理尺寸计算 |
| 圆角 | `min(h/2, 28 × scale)` | 与 Apple 44pt 无关；展开态不做"越圆越好" |
| 高度分档 | 短档 80 / 媒体 124 / 歌词·Agent 196 | **按内容决定高度**，不用统一大容器再留白 |
| 收起态 | 1 条主信息 + ≤ 4 枚小圆 | 并行任务只给"有几件"的线索，不堆叠详情 |
| 展开态信息层级 | ≤ 3（身份 / 内容 / 操作） | 渐进披露，避免变成二级菜单 |
| 安静态 | 10px 圆点，α ∈ [0.12, 0.30]，呼吸周期 4s | 可确认存在但不形成视觉焦点 |
| 动效 | 弹簧 ζ ≈ 0.68，单次 ≤ 400ms；进入 ≤ 250ms、退场 ≤ 167ms（**入慢退快**，取自 WinUI3 `ControlNormal/ControlFast`）；只用于状态变化，Reduce Motion 降级为 fade |
| 正文对比度 | ≥ 4.5:1（WCAG AA） | 材质不能牺牲可读性 |

常量落在 `contracts/BalanceRules.hpp` 与 `core/balance.py`，
由 `tools/check_contracts.py` 校验两侧一致。**规则必须是可断言的数字，
不能只写在文档里。**

> 历史说明：`core/tokens.py` 里的 44pt / 84–160pt / ≤2000ms 是**调研参照值**
> （WWDC23 10194），不是平衡岛采用值。v0.2.0 起明确区分，避免设计 token 漂移。

## 4. 交互语义（逐手势定义）

| 手势 | 语义 | 不做什么 |
|---|---|---|
| 单击胶囊 | 渐进披露：展开 / 收起 | 不抢焦点、不弹模态 |
| 双击 | 一览：并置所有并行任务 | 不进入"应用模式" |
| 点小圆 | 切换当前焦点到那一件 | 不把小圆做成菜单 |
| 点标题 | **回原应用** | 不在岛内打开二级界面 |
| 拖进度 / 五个走带钮 | 媒体的最小必要控制 | 不扩展到播放列表、歌词编辑 |
| `×` | dismiss **这一条** | 不是退出程序 |
| **按住 Ctrl** | **让路**：鼠标穿透 + 降透明度 | 不结束进程、不改变配置 |
| 右键 / 托盘 | 设置、暂停 30 分钟、退出 | 托盘是唯一固定入口 |
| 全屏应用 | 自动退让为把手 | 不在全屏内容上盖 island |

「让路」是平衡岛独有的交互语义：它把"是否遮挡"的决定权交回用户，
而不是让用户去设置里翻开关。

## 5. 视觉规范

- **形状**：圆角胶囊；安静态为正圆（由 `min(h/2, …)` 自然得到）
- **材质三档**：液态玻璃（顶部镜面线 + 折射亮环）/ 磨砂 / 实色。
  任何一档在浅色壁纸上都必须可读
- **描边双层**：整圈**均匀淡描边**保证连续性 + 顶部一条高光带保证"顶光"质感；
  高光带高度 = 圆角半径，渐变末端色等于底色，带下沿无接缝。
  **禁止整圈等高亮**（会变成镀铬边框，也会点亮竖边造成双重边）
- **描边宽度**：`clamp(h × 0.024, 1.5×scale, 3.2×scale)`，随胶囊尺寸缩放
- **色彩语义**：涨红跌绿（中国习惯）；Agent 运行 / 等待输入 / 完成三态；
  品牌色不参与信息编码
- **文字**：中文优先；字号随 DPI；正文对比度 ≥ 4.5:1
- **动效**：只在状态迁移时出现，不做装饰性循环动画（呼吸点除外）

## 6. 扩展能力与边界

**开放**：
- Provider 接口隔离，单个数据源异常不影响其他源
- 命名管道 `\\.\pipe\BalanceIsland-v1`：单行 JSON + `\n`，一次连接一条消息，
  任意语言三行代码可推送；队列上限 256 防止 Flood
- `rules.json` 本地配置，原子写 + 版本迁移；跨语言契约校验

**明确不做**（写进边界比事后解释更省事）：
- 不读聊天正文（隐私与风控，同类项目也主动掐住这条）
- 不做账号、云同步、订阅分级
- 不内嵌浏览器引擎做常驻壳
- 不注入 `explorer.exe`，不改系统 shell
- 不把岛做成应用启动器 / 剪贴板管理器 / 待办工具的替代品

## 7. 范式如何被验证

| 层 | 手段 |
|---|---|
| L1 契约 | `check_contracts.py` 比对 C++ / Python 常量；`naming.py --check` 查旧称 |
| L2 确定性 | 569 项断言；布局分档、信息层级、动效裁剪均有纯函数与边界用例 |
| L3 实机 | `layout_probe` 出图 + 人工清单；自动化通过**不得**表述为视觉已验收 |

新增功能若无法对照本文件说出「它维持了哪条平衡」，就不该进主分支。

### 关键规则的外部依据（编号见调研报告）

| 本范式规则 | 依据 |
|---|---|
| 展开态信息层级 ≤3、隐藏层级 ≤2 | Nielsen progressive disclosure；Xerox Star (1982) |
| 收起态 ≤1 主信息 + ≤4 小圆 | Cowan 工作记忆 ~4 chunks；Glanceable Peripheral Displays (DIS'06) |
| 安静态低幅度连续变化、不弹窗/发声 | Calm Technology 8 原则；Ambient Displays (CHI'98) |
| 进入 250ms / 退场 167ms，入慢退快 | WinUI3 `ControlNormal/ControlFast`；Apple HIG 动画 ≤2s |
| 正文对比度 ≥4.5:1、非文本 ≥3:1 | WCAG 2.2 SC 1.4.3 / 1.4.11 |
| 抓屏静止时零开销、失败仍可用 | Calm Tech「default to usable state」；社区 DXGI + 内容哈希实践 |
| 不注入 `explorer.exe`、独立 topmost 窗口 | Win11 无受支持的第三方任务栏 UI 扩展点；ExplorerPatcher 反例 |
| Provider 接口隔离、配置原子写与版本迁移 | Windows Widget Provider 进程外 COM；PowerToys 命名管道 + JSON；Ice `MigrationManager` |
| 全屏主动退让、只让该屏隐藏、热键仍可唤出 | `SHQueryUserNotificationState` 三 busy 态；Wallpaper Engine / Lively 全屏卸载资源 |
| 托盘 + 明确退出是硬要求 | V2EX 2021 首例最集中差评「咋关掉」；全行业已趋同 |
