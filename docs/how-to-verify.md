# 怎么验证「实际效果」

这份文档只回答一件事：**现在这个仓库能跑出什么、你该点什么、看到什么算通过。**

先说清边界，避免期望错位：

| 你看到的 | 它是不是真的 |
|---|---|
| 桌面上浮出的胶囊、动画、状态切换 | **是真的**，一个独立 `.exe` 用分层窗口 + GDI+ 画在你的桌面上 |
| 胶囊里的歌名 / 通知 / 复制内容 / 文件名 / 盘符 | **是真的**，全部来自你机器的实时状态（SMTC / 通知监听 / 剪贴板 / 下载目录 / WM_DEVICECHANGE） |
| 「哪些操作要响应」的开关与黑名单 | **是真的**，改完保存即刻生效，热加载不需要重启 |
| 毛玻璃亚克力、任务栏融合 | **还没有**，需要 DWM 材质；当前是模拟玻璃 |
| 全屏自动避让 | **是真的**，用 `SHQueryUserNotificationState` 检测全屏 / 演示 / D3D 独占 |

## 30 秒路径（最快）

在资源管理器里双击：

```
balance_island\build\cpp\balance_island.exe
```

如果还没编译过，先在项目根目录跑一次：

```bash
bash tools/build_cpp_msvc.sh
```

然后双击上面那个 exe。屏幕**顶部居中**会出现一条深色胶囊，第 1 秒开始走剧本，18 秒一轮循环。

- **左键点胶囊** → 展开 / 收起
- **右键点胶囊** → 菜单：设置 / 暂停 30 分钟 / 退出
- 不想让它一直跑 → 命令行加 `--duration=20000`（20 秒后自动退）

## 验证「复制会被识别」+「能屏蔽」（30 秒）

```bash
# 1) 启动（默认读真实系统）
build\cpp\balance_island.exe

# 2) 随便复制点什么（记事本、浏览器、VS Code 都行），岛应该在 1 秒内出现「已复制」
#    右侧小字是复制来源的进程名，例如 Code / chrome / WorkBuddy

# 3) 右键 → 设置 → 在「这些应用不提示」里写一行 wechat → 保存
#    再从微信复制一次：岛**不再出现**，而日志里会写一行原因：
#    [t=+1.68s] blocked: clipboard/app-blocked(wechat)
```

判定标准（三条都要满足）：

| 检查点 | 通过的样子 |
|--------|-----------|
| 识别 | 日志出现 `+clipboard 「已复制」`，屏幕出现胶囊，约 3 秒后自动消失 |
| 去重 | 同一份剪贴板不会反复弹；连续复制两次会有两次提示 |
| 拦截 | 命中黑名单时**没有** `+clipboard`，只有 `blocked: .../app-blocked(...)`；胶囊保持隐藏 |

改配置文件也能热加载（不用重启）：

```bash
# 文件位置
%APPDATA%\balance_island\rules.json

# 改完保存，1 秒内日志出现：
rules reloaded: ok
```

故意写坏（删掉一个逗号）应该看到 `rules reloaded: ignored (配置解析失败：...)`，
而胶囊继续按上一份可用配置工作 —— 这是刻意设计，不是 bug。

设置窗口本身也能自检（不需要人点，用于回归）：

```bash
build\cpp\balance_island.exe --selftest
# → selftest: app_block=2 first=wechat volume=0 quiet=1 22:30
# → 结果写到 build\cpp\settings_selftest.json，不动你的真实配置
```

## 验证「专辑封面」（可选，需要真的在放歌）

用网易云 / QQ 音乐 / 浏览器播一首有封面的歌，岛展开后左侧应该是**那张封面**，
不是色块加音符。封面缓存在：

```bash
%LOCALAPPDATA%\balance_island\covers\<hash>.png
```

没在放歌时想验证这条链路，可以用注入探针造一个真实会话（静音，不出声）：

```bash
build\cpp\media_inject_probe.exe 40                       # 造一个带封面的 SMTC 会话
build\cpp\cover_probe.exe                                 # 逐段打印会话/属性/封面流大小
```

## 验证「真实数据」（这一步才是关键）

默认模式读的是你的真实系统。下面每个动作都能在几秒内看到结果，且全部可自证。

| 你做什么 | 预期看到 | 如果没看到，查这里 |
|----------|----------|-------------------|
| 在网易云 / QQ音乐 / B站 / 浏览器按下播放 | 胶囊出现在顶部居中，显示**真实歌名**、歌手·专辑、右侧 `0:18 / 2:00` 格式的实时进度 | `balance-island.log` 里找 `live media=`，若为 `none` 说明系统没有活跃会话（部分播放器不注册 SMTC） |
| 暂停播放 | 胶囊保留但律动条停止、优先级降到 45（若同时有通知会主动让位） | — |
| 退出播放器 | 胶囊自动消失（不是残留上一首） | 若残留，说明 `persistent_ids` 结束逻辑失效 |
| 复制任意文字 | 出现「已复制」胶囊，3 秒后自动退场 | 日志 `clip_seq` 是否递增 |
| 往「下载」文件夹放一个文件 | 显示真实文件名，8 秒后退场 | 日志 `+download` |
| 按音量键 | 显示「音量 N%」，2.5 秒退场 | 日志 `vol=` 是否变化；无声卡时该源不工作 |
| 拔掉电源且电量 <20% | 显示「电量低 / 剩余 N%」 | 台式机无电池不触发 |
| 全屏玩游戏 / 放全屏视频 | 胶囊自动隐藏并暂停采样 | `fullscreen=1` 应出现在日志 |
| 让某个应用弹一条通知 | 显示通知标题（6 秒） | 见下方「通知的已知边界」 |

**怎么确认它真的在读系统、而不是在演**：日志里 `vol=76%` 应该是你系统当前的音量；
把音量拖到 30%，日志应在 1 秒内变成 `vol=30%`。`clip_seq` 每次复制都会跳。

### 通知的已知边界

`UserNotificationListener` 的「新消息」判定是**通知 id 集合差集**：

- 微信等同一条通知被撤回或更新（id 不变）时，可能不触发
- 首次启动只建立基线，不会把系统里已有的历史通知刷出来（这是刻意的）
- 权限一旦被系统收回，`notif.ok` 变 false，该源静默失效，日志里 `notif_seq` 不再增长

### 我用来验证的探针（你可以自己跑）

```bash
# 读当前系统媒体会话（只读，不干扰播放）
build/probe/smtc_probe.exe

# 建一个静音的真实 SMTC 会话，用于验证媒体链路（不出声）
build/probe/media_inject_probe.exe --hold=30

# 看通知监听权限状态
build/probe/notif_probe.exe
```

## 剧本时间轴（`--script` 模式，每秒该看到什么）

| 时间 | 胶囊形态 | 发生了什么 | 用来验证的核心域能力 |
|---|---|---|---|
| 0–0.6s | 不显示 | 无活动 | 空闲时不占位 |
| 0.6s | 紧凑胶囊 | 媒体开始播放（红色音符块 + 歌名 + 律动条） | 单活动 → 紧凑呈现 |
| 2.6s | 多出右侧小圆 | 日历加入（优先级 90 > 媒体 60） | 高优先级抢占主位，次位降为分离小胶囊 |
| 3.6–5.8s | 展开大胶囊 | 日历展开：标题 / 时间地点 / 还有 12 分钟 | 三态里的 `expanded` 与弹簧过渡 |
| 7.0s | 主位不变 | 第三个活动（下载，优先级 85）加入 | 最多显示 2 个，其余被抑制 |
| 8.6s | 下载从画面消失 | 模拟桥接进程断开 | **桥接离线降级**：`bridge.*` 活动被过滤，内置活动照常显示 |
| 10.4s | 下载重新出现 | 桥接恢复 | 恢复后自动重新参与调度 |
| 11.6s | 回到以媒体为主 | 日历结束 | 主位重排 |
| 12.0s 左右 | 下载过期消失 | 到达 `staleDate` | 过期自动结束并触发重调度 |
| 13.2–14.4s | 整条消失 | 模拟进入全屏 / 反作弊程序 | **暂停采样并隐藏**，活动状态保留不丢 |
| 15.6s | 消失 | 全部活动结束 | 回到空闲 |
| 17.6s | 重新开始 | 剧本重置 | 循环 |

底部那行小字（`Compact · vis 1 · sup 0 · exp 0`）是调试状态行：
`state` 胶囊状态、`vis` 可见数、`sup` 被抑制数、`exp` 本次过期数。
不想要就加 `--no-hud`，观感更接近成品。

## 三态截图（不用开程序也能看）

`tools/verify_visual.sh` 会自动生成三张 PNG：

```bash
bash tools/verify_visual.sh
```

产物在 `build/`：

| 文件 | 内容 |
|---|---|
| `snap_compact.png` | 紧凑态：媒体播放，音符块 + 歌名 + 律动条 |
| `snap_minimal.png` | 极简态：日历抢占主位 + 媒体降为右侧分离小圆 |
| `snap_expanded.png` | 展开态：标题 / 时间地点 / 底部操作提示 |
| `desktop_proof.png` | **桌面实证**：从屏幕 DC `BitBlt` 抓回的「胶囊 + 真实桌面背景」 |

最后一张是关键的诚实证据：它抓的不是程序自己的绘制缓冲，而是显示器上合成后的画面，
所以能证明胶囊确实叠在你桌面上，而不是只存在于内存位图里。

## 可复现的验证分级

| 层级 | 手段 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| L1 逻辑 | `bash tools/build_cpp_msvc.sh`（69 + 20 项断言） | 调度、过期、状态机、降级、进度解析正确 | 画得好不好看 |
| L2 像素 | `bash tools/verify_visual.sh`（三态 + 桌面抓取） | 布局、文字不截断、材质有透明、确实在桌面上 | 动画是否顺滑、60fps |
| L3 观感 | 你自己双击跑一轮 | 手感、节奏、可读性 | 其他机器 / 其他 DPI |

三层不能互相替代：L1 全绿也可能是丑的，L2 好看也可能是逻辑错的。项目铁律见 `CONTRIBUTING.md`。

## 命令行参数

| 参数 | 作用 |
|---|---|
| `--duration=毫秒` | 到点自动退出，脚本化验证用 |
| `--no-hud` | 隐藏底部状态行 |
| `--no-script` | 不跑内置剧本，只等手动交互 |
| `--snapshot=路径.png` | 在 `--snapshot-at` 时刻把**自身绘制结果**存成 PNG（含透明通道） |
| `--snapshot-at=毫秒` | 配合 `--snapshot` / `--grab` 使用 |
| `--grab=路径.png` | 在 `--snapshot-at` 时刻从屏幕 DC 抓取桌面实际画面 |
| `--log=路径.log` | 指定日志，默认 exe 同目录 `balance-island.log` |

日志只在**可观察状态变化**时写一行，例如：

```
DIW overlay start 2026-11-12 15:45:18
scale=2.000000  workarea=3840x2160
[t=+0.00s] state=Idle visible=0 suppressed=0 expired=0 bridge=on suspend=off
[t=+0.63s] state=Compact visible=1 suppressed=0 expired=0 bridge=on suspend=off
[t=+2.62s] state=Minimal visible=2 suppressed=0 expired=0 bridge=on suspend=off
```

## 已知未验证 / 可能偏离预期的部分

1. **材质**：目前是「深色半透明 + 顶部高光」模拟玻璃，不是 DWM 亚克力/云母；系统设置里关掉「透明效果」也不会跟着变。
2. **多显示器**：只取主显示器，多屏下不会跟随鼠标所在的屏幕，DPI 只在启动时读一次。
3. **全屏避让**：逻辑开关在，但没有全屏检测，真实游戏/播放器不会自动触发。
4. **反作弊**：不注入任何系统进程（这是刻意的，规避 ZenDesktop 踩过的坑），所以理论上不会被 ACE 扫描；但也因此拿不到任务栏内部数据。
5. **性能**：60fps 是目标节奏，实测帧间隔 P95 与常驻内存**还没测**，`docs/verification.md` 里没有这组数字。
6. **资源释放**：进程退出后窗口与 DIB 释放正常，但长时间运行（小时级）未做泄漏观察。

需要继续往前推进的话，下一步是 S5：把剧本换成真实 Provider（媒体会话 / 通知 / 电池），
以及决定要不要做成 Windhawk mod（能拿到任务栏数据，但要进 `explorer.exe`，风险与隔离性要重新评估）。
